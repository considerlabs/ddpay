### 0.5 핵심 유저 플로우

1. **로그인 → 홈 → 계약등록(1~4) → 완료 → 등록현황**

## 3. 신규계약 등록 `/contract`

### 공통
- PageHeader `신규계약 등록` (step>1 시 뒤로=이전 스텝)
- 상단 progress bar (green, step/4)
- 하단: 이전(선택) + 다음/완료

### Step 1 — 계약 유형
- 안내: `계약 유형을 선택해주세요.`
- 3×2 그리드: 월세/경조사비/학원비/운영비/인건비/배달비 (이모지+라벨). 선택 시 green border + light bg
- 계약명 Input
- 다음 활성 조건: 유형 + 계약명

### Step 2 — 거래 상대방
- 안내: `거래 상대방의 정보를 입력해주세요.`
- 라디오: 개인 / 사업자
- 필드: 성명, 주민번호|사업자등록번호, 은행 select, 계좌번호
- 은행 미선택 시 red border + `은행을 선택해주세요.`
- 은행+계좌 입력 후 `안심 계좌인증` (orange outline)
- 인증 후 green 체크 문구
- 고지: 유효성만 검사, 상대방 연락 없음

### Step 3 — 금액·결제방식
- 송금자명칭 (+ `송금자명 변경방법 ⓘ`)
- 송금금액 (원)
- 결제금액 = 송금액 × 1.066 (읽기전용, `송금액+서비스이용료(6.6%)`)
- 자동결제 여부: `내가 직접결제하기(수동)` / `자동결제 신청하기` (선택 시 orange border)

### Step 4 — 첨부서류
- 3종 추가 버튼(green outline +): 신분증/사업자등록증, 입금 통장 사본, 임대차계약서 등
- 추가된 파일 행 + X 삭제
- CTA: `계약등록 완료`

### Step 5 — 완료
- 큰 아이콘 + `계약등록 완료!` (green)
- `계약 등록 현황 바로가기` → `/status`

### 디스크립션
승인 대기 없이 mock은 즉시 승인완료로 저장되어 바로 결제 가능하다고 안내.

## 5. 수동 결제 시트 (모달, `/status` 내)

### 공통 셸
- dim 오버레이 + 중앙 시트 (max-w-xs, max-h 85vh, scroll)
- 상단: 카드 아이콘 원형(orange-light) + 계약명 + StatusBadge

### 5-A. 카드선택
- 가로 스크롤 카드(그라데이션 블루). 선택=orange ring, 비선택=opacity 50
- 선택 카드명(last4) 표시
- 취소 | 다음

### 5-B. 일반결제 확인
**정보 테이블**
- 받는사람 / 받는계좌 / 통장표기 / 송금액 / 결제금액 / 결제카드 / 결제구분=`일시불`
- 결제일(오늘)

**탭**: 일반결제(활성) | 분할결제

**결제금액 편집**: 큰 금액 + ✎ → number input (blur 확정)

**CTA**: 카드선택 | 결제하기 (금액>0이면 활성)

**디스크립션**: 일시불 1회 승인. 분할 UI 없음. 탭 전환 시 분할 플로우로 이동.

---

### 5-C. 분할결제 상세 프로세스

#### C0~C9. 프로토타입 화면 넘버링 (10-1 ~ 10-9)

| 번호 | 화면 | 상태 |
|---|---|---|
| 10-1 | 규칙안내 | 구간표·칸수 산정 안내 |
| 10-2 | 빈입력 | 미입력 → disabled |
| 10-3 | 입력중 | 자동잔액 실시간 |
| 10-4 | 동일금액 오류 | duplicate → disabled |
| 10-5 | 합계초과 오류 | lastAmount &lt; 0 → disabled |
| 10-6 | 잔액0 오류 | lastAmount === 0 → disabled |
| 10-7 | 유효(결제가능) | splitValid → 결제 활성 |
| 10-8 | 5칸 예시 | ≤3천만 구간 UI |
| 10-9 | 전체 플로우 | E2E 다이어그램 |


#### C0. 진입 / 규칙안내 (10-1)
- 탭을 분할결제로 전환하면 결제금액 기준으로 **입력칸 수 N** 산정
- 안내 카드에 구간표를 노출 (프로토타입 10번 화면)

| 결제금액 구간 | 입력칸 수 N |
|---|---|
| ≤ 10,000,000 | 3 |
| ≤ 30,000,000 | 5 |
| ≤ 50,000,000 | 7 |
| ≤ 70,000,000 | 9 |
| ≤ 90,000,000 | 11 |
| > 90,000,000 | **11 (임시, 기획 확정 필요)** |

- 정보 테이블 `결제구분` = `분할결제(N회)`
- ✎로 금액을 바꿔 구간이 바뀌면 **칸 재생성 + 기존 입력 초기화**

#### C1. 빈입력 (비활성)
- 1~(N-1) 칸 placeholder `금액 입력`
- N번째 칸 = 총액 (아직 앞칸 0이므로 총액 그대로), 라벨 `자동`, 읽기전용
- 안내: `모든 회차에 금액을 입력해야 결제하기 버튼이 활성화됩니다.`
- **결제하기 disabled**

#### C2. 입력중 (자동잔액)
- 사용자가 1~(N-1) 입력 → `lastAmount = 총액 − Σ(1..N-1)` 실시간 반영
- 합계 요약 바: 입력합 / 자동잔액
- 포커스 칸은 orange border
- 자동 칸은 green-light 배경

#### C3. 검증 규칙 (모두 충족해야 활성)
```
splitAllFilled = (1..N-1 모두 > 0) AND (lastAmount > 0)
splitHasDuplicate = unique(입력된칸 ∪ {lastAmount}) 개수 불일치
splitValid = splitAllFilled AND NOT splitHasDuplicate
```
- 빈 칸은 중복 판정에서 제외 (0으로 채운 빈칸끼리 중복 오판 방지)
- 금액이 **완전히 동일**하면 거부 (100원 차이도 “다른 금액”으로 허용)

#### C4. 에러 상태 화면
| 상태 | UI | 문구 | CTA |
|---|---|---|---|
| 동일금액 | 중복 칸 red 하이라이트 | `⚠ 각 회차 금액은 서로 달라야 합니다. (동일 금액 불가)` | disabled |
| 합계초과 | 자동칸 red 음수 | `입력한 금액의 합이 결제금액을 초과했습니다.` | disabled |
| 잔액0 | 자동칸 0 | `마지막 회차에 남는 금액이 없습니다. 다른 회차 금액을 줄여주세요.` | disabled |
| 미입력 | — | gray 안내 문구 | disabled |

#### C5. 유효 (결제가능)
- 회차별 금액 목록 + ✓ 합계=총액 + ✓ 중복없음
- **결제하기 orange 활성**
- 탭/정보테이블에 `분할결제(N회)` 명시

#### C6. 구간별 UI 예시
- 3칸: 총액 ≤1천만 (기본)
- 5칸: 총액 ≤3천만 (시트 스크롤)
- 7/9/11칸: 동일 패턴, 행만 증가

#### C7. End-to-end 플로우
```
카드선택 → 탭(분할) → 금액확정(칸수산정)
  → 회차입력 → 검증
      ├─ OK → 결제하기 → 완료모달 → 목록 카운트+1
      └─ NG → 경고 유지 / 결제 disabled
```

### 5-D. 완료
- `결제가 요청되었습니다. 결제 결과는 결제내역에서 확인하세요.`
- 확인 → 목록 `결제완료` 카운트 +1, 시트 닫힘

### 디스크립션
일반/분할을 **별도 화면 상태**로 설계·문서화한다. 분할은 금융 리스크(동일금액 제한)가 핵심이므로 에러 상태를 개별 화면으로 명시한다.

## 6. 등록현황 상세 `/status/[id]`

### 섹션
1. **기본 정보**: 서비스분류, 계약등록번호(`4601{id}`), 계약명+`사용중지하기`, (배달비 시 플랫폼사/사업자), 등록일, 결제방식, 결제일=미지정, 승인상태, 반려사유

3. **계좌송금 등록내역**: 은행/계좌/예금주/`송금자명칭`+수정 버튼 + 안내 각주
4. **카드결제 및 계좌송금 완료내역**: 횟수·금액 요약 + 결제내역 상세 안내

### 디스크립션
읽기 중심 DetailRow. 사용중지/송금자 수정은 orange 소형 버튼.

## 7. 구매내역 `/payments`

### 레이아웃
1. Header `구매내역`
2. 탭: 전체 / 계약결제 / B2B도매몰 / 식자재몰 (활성 green underline)
